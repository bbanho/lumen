# ADR-001 — A gramática como sistema

**Status:** aceito
**Data:** 2026-09-26
**Contexto:** Bluefin/Silverblue, kernel 7.1.13-200.fc44.x86_64, Landlock ABI 9

## Contexto

Sistemas de agente contemporâneos dão ao modelo uma tool `bash` que executa com
os bits do usuário, e cercam isso de camadas de *aprovação* — prompts, floors,
gates. A própria docstring upstream de um deles admite:

> *"Every guard here is defense-in-depth, **NOT a security boundary**: the
> terminal tool runs as the same OS user and can read/write anything."*

Não é bug. É modelo de privilégio. Um prompt injection não negocia com um
`approval` que o próprio modelo pode simplesmente não pedir.

Separadamente, o mesmo sistema é um monólito: centenas de milhares de linhas
tentando ser TUI + CLI + dashboard + daemon + cron + mensageiros + vault +
browser ao mesmo tempo. Estados compartilhados entre processos de longa vida é o
que o torna um.

## Decisão

Construir um sistema onde **o vocabulário é a fronteira**, e a fronteira é
imposta pelo kernel — não por convenção.

Formalizado como:

> O vocabulário de um sistema é o conjunto de nomes que ele pode dizer.
> Distroless é o que torna esse conjunto explícito.

Distroless não significa "sem dependências". Significa **sem identificadores
não-ligados**: `sh` não é uma feature, é um nome que resolve para código
arbitrário. Um interpretador no namespace é um `eval` no vocabulário do sistema.

## Consequências

### 1. Gramática, não política

Um plano que nomeie uma capacidade não montada **não compila**. Não é "recusado
por uma regra" — é um nome inexistente. O kernel é o type checker, e isso é
à prova de modelo hostil: não há camada de interpretação para subornar.

### 2. As duas metades são assimétricas — e a distinção é o ponto

| | Quem fecha | Mecanismo | Contra modelo hostil |
|---|---|---|---|
| **Vocabulário** | compositor + kernel | namespace / Landlock | sim |
| **Veracidade** | a tool | syscall real + exit code | **não** — é defense, não garantia |

Medido: uma tool que imprimia JSON sem tocar o filesystem **afirmou uma escrita
inexistente com exit 0** quando `/w` não estava montado. O isolamento fecha o
vocabulário; não fecha a mentira. Fechar a veracidade é trabalho da tool, e o
compositor reescreve stdout a partir do exit code — nunca o contrário.

Esta assimetria é o conteúdo do ADR. Uma formulação que tratasse as duas como
"segurança do sistema" seria falsa.

### 3. Re-derivação em vez de recuperação

Se toda operação é função pura do transcript, o estado é cache. Medido: 200
passos re-derivados em 1.2 ms, mais barato que executar (1.8 ms) e que descartar
(2.26 ms). Replay é mais barato porque re-derivar não custa I/O.

### 4. Isolamento a custo zero elimina a necessidade de daemon

`bwrap` com `unshare-all` completo: 0.00 s. `sel` lacra em `main()` sem bwrap,
sem systemd, sem compositor. Custo zero permite um processo novo e confinado por
operação — e torna o daemon persistente desnecessário, que é justamente o que
faz um monólito.

### 5. Efeito externo não tem snapshot — tem journal

`/snap` restaurável; `/fora` imperdoel. `git push` publicado, chave consumida,
API chamada: nenhum snapshot de mundo recupera. A resposta honesta é
**compensação** — desfazer é outro passo nomeado, journalizado antes do efeito.

O compositor existe por isso: ser o único ponto onde o efeito é nomeado antes de
acontecer. Sem ele, cada tool é uma ilha com poderes próprios; com ele, o
transcript é a única autoridade.

## Limites declarados

1. **Não é um monolito para o usuário final.** É substrato de composição.
2. **Não conserta a confiabilidade do modelo** — conserta a confiabilidade do
   *sistema*. São coisas diferentes.
3. **A veracidade é convenção honesta**, e convenção honesta é o que um LLM pode
   quebrar. O que a reduz a defense-in-depth: o compositor reescreve stdout pelo
   código, e a spec declara qual código é obrigatório para qual efeito.
4. **Sem moat.** Qualquer um com Landlock pode fazer isso.

## Alternativas rejeitadas

| Alternativa | Por que não |
|---|---|
| Reescrever um agente existente em Rust | 561k LOC de Python; consumidor puro de upstream (0 commits à frente, árvore limpa). Portar é para sempre, sozinho. |
| Electron → Docker, mantendo o backend | O `Dockerfile` upstream **já faz isso** (node stage → `npm run build` → `HERMES_WEB_DIST`); Electron não entra na imagem. Esforço zero. Nginx seria danoso: `web_server.py` já faz `mount_spa`. |
| `network_mode: host` como isolamento | É o oposto. Dá ao container todo o loopback do host. Sem `cap_drop`, `read_only` nem `security_opt`. |
| D-Bus como barramento | Exige `.service` + policy XML + introspectable objects para resolver um problema que não existe. 15 linhas de unit file fazem o mesmo. |
| Flatpak portal como RPC | Portals são file/print/screenshot. RPC próprio é socket; se for app Flatpak, D-Bus próprio, não `org.freedesktop.*`. |
| Snapshot de disco como garantia de segurança | Snapshot é sistema de arquivos. Não tem jurisdiction sobre rede, memória ou efeito externo. |
| Nix/Guix como "distro-less" | Resolvem *reprodutibilidade de build*, que é outro eixo. O problema é fronteira de syscall, não reprodutibilidade. |
